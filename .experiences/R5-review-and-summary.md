# R5 镇街/区县审核汇总人员：盯异常，确认自动汇总

## 这一页解决什么事

你不再把基层表格手工拼成一张总表，而是看系统已经汇总好的结果，集中处理异常、口径冲突和质量证据。你的判断会决定本轮补差结果能否进入交付链和回流资源池。

## 你手上拿到的真实输入

- 待汇总申请：来自 R1/R2 的申请和审批边界。
- 区域与组织：例如 `济南市教育局`、`历下区` 的补录结果，全部锚 `sd-default` 单租户单省。
- 字段口径：`字段格式`、`是否允许为空`、时间窗、来源说明。
- 质量证据：缺失率、格式异常、字段冲突、schema 变化提示。
- 状态：待汇总、退回修改、待交付、已回流。
- 治理大盘入口：旧 `data-operation-board-front` 的 supply-demand、data-usage、data-objection、direct-data-access。
- 用数反馈：用数方对汇总口径、字段结果、交付方式或直达结果提出异议。四类来源由 `portal-vue /feedback/*` 真实表单证实——数据异议、资源申请异议、数据使用异议、网站反馈。
- 异议处理四子流程：旧 `dsp_handling` 的 `data_objection` / `data_objection_evaluate` / `data_objection_process` / `data_objection_authz` / `data_objection_use` 真实包含"受理 → 评估 → 处置 → 授权 → 用数闭环"五段（评估含 evaluate 一段）；本端承接评估、处置、授权、用数四段（受理由 R1 反馈入口完成）。
- 需求任务派发：R7 判定 R1 业务需求不可复用时，本端接收"需求任务派发"，按区域/部门/字段切片成基层任务卡，派给 R3/R4；任务完成回流后回到本端汇总。
- 自动检测任务受影响：旧 `catalog_quality_task` / `catalog_quality_task_log` / `catalog_quality_task_result` 的任务失败或规则口径变更会冲击你的汇总，本端只解释影响范围，不替 R6 改规则、不替 R8 督查执行器问题。
- 旧状态映射：旧 `审核中(2)/发布(3)/撤销` ↔ 新 `pending_review/active/revoked`；汇总状态以 catalog3-metadata3 重构方案 §八 为准。

## 一条主旅程

1. 打开待汇总任务，先看完成率、异常分布、逾期情况、自动/人工质量检测结果和交付授权状态。
2. 下钻异常字段，区分是基层漏填、字段口径冲突、时间窗不一致、资源 schema 变化，还是资源下架、目录撤回或 active 版本切换影响。
3. 对可修正的基层差异，退回指定 R3/R4 任务，并写清字段、原因和期望值范围。
4. 对口径问题，转 R6/R7 调整目录项、资源字段绑定或共享说明，不在汇总页临时改规则。
5. 对交付链缺授权、续期失效或分级授权不足的问题，转 R2/R7 处理，不线下导出结果。
6. 对供需、用数、异议和数据直达看板里的问题，按反馈四类（数据异议 / 资源申请异议 / 数据使用异议 / 网站反馈）分别归集，定位是补差、口径、资源、授权还是 projection 问题。
7. 异常收敛后确认自动汇总，系统生成可回放的汇总快照。
8. 复核关键指标是否符合申请范围，确认进入 `delivery_task`、已审批数据直达或回流资源池。
9. 将本轮质量问题沉淀为下次预填和校验规则；若发现汇总后口径错配，撤回本次汇总并保留影响范围。
10. 对从 R7 派下来的"需求任务派发"，按区域、部门、字段切片为 R3/R4 任务卡（每卡只指定一个区域 + 一组字段 + 一个时间窗），任务回流后由本端做差异归并，输出"业务需求满足度"摘要回 R7。
11. 对异议处理四子流程：评估异议是否成立（口径/质量/血缘/审批/范围/交付/直达哪一类）；处置阶段决定退回 R3/R4、转 R6/R7、转 R2 或解释关闭；授权阶段确认是否影响在途授权或订阅；用数阶段记录用数方反馈是否接受处置结果。每段都进 `data_objection` projection，不在线下沟通。
12. 对自动检测任务失败或规则变更的影响，只标"哪些汇总记录受影响"，转 R6 改规则、转 R8 督查执行器；本端不擅自改字段口径。

## 关键判断点

| 你看到什么 | 该怎么判断 | 系统证据 |
| --- | --- | --- |
| 某区完成率低 | 先看是否任务范围或时间窗设置不合理 | `application_record`、任务分派记录 |
| `字段格式` 大量异常 | 可能是模板口径不适配 | `catalog_model_field`、quality projection |
| `是否允许为空` 冲突 | 不能手工放行，需口径确认 | `catalog_item` 版本和 R6/R7 确认记录 |
| 汇总指标跳变 | 要求来源证据或退回复核 | schema snapshot、历史回流 |
| 资源字段变化 | 汇总暂停，转提供方确认 | `resource_schema_mapping`、schema version |
| 资源下架或 active 版本切换 | 暂停交付，按 active 版本重新汇总 | `resource_asset.status`、schema version |
| 交付链缺授权 | 不线下导出，回到审批授权链 | `approval_case`、`delivery_task.access_grant_snapshot` |
| 用数异议集中出现 | 按反馈四类分别归集，先定位是口径、补差、资源还是 projection | 用数异议 projection、summary snapshot |
| 数据直达请求绕过审批 | 拒绝直连，回到已审批交付链 | 数据直达交付回执、approval case |
| 数据直达结果与汇总口径不一致 | 暂停直达交付，核对审批范围与资源版本 | 已审批数据直达交付回执 |
| 异议进入"评估"阶段卡住 | 按四类做归因；不让评估悬挂超过 SLA | `data_objection_evaluate` projection |
| 异议处置后用数方仍不接受 | 走"用数"阶段记录意见，必要时升级 R2/R7；不在线下劝退 | `data_objection_use` projection |
| 需求任务派发回流字段不一致 | 不强行归并；标"待口径裁决"回 R7 | demand task link、归并备注 |
| 自动检测任务连续失败导致空汇总 | 暂停本轮汇总，转 R6 改规则、转 R8 查执行器 | task log、quality projection |

## 异常分支

- **持续多次退回**：升级为目录字段或任务口径问题，不继续压基层修改。
- **关键指标跳变异常**：要求补充来源证据后再放行。
- **汇总后发现口径错配**：撤回本次汇总，保留撤回原因和影响范围。
- **质量 projection 与现场判断不一致**：以业务审核为准，但保留差异证据给 R6/R8 复查。
- **交付链缺授权**：不线下导出，回到 R2/R7 检查审批与授权回执。
- **用数方提出异议**：保留异议摘要和证据，定位到补差、口径、资源、授权或 projection，不在线下重算。
- **数据直达结果与汇总不一致**：暂停直达交付，核对审批范围、资源版本和汇总快照。
- **异议四子流程出现绕行**：评估、处置、授权、用数任一段被线下推进，必须重新进系统留痕；R8 抽查。
- **需求任务派发被基层视作"全表重填"**：要求按字段差异切卡，不允许把任务变成历史数据回填。
- **自动检测规则变更让历史结论失真**：以新规则为准重算受影响范围，旧结论保留为历史 evidence，不静默覆盖。

## 成功判据

- 你处理的是异常、口径和质量，不是全量重审。
- 每次退回都定位到字段、对象、原因和责任环节。
- 自动汇总结果能直接进入交付或回流，不再二次线下拼接。
- 本轮问题会反哺目录字段和质量规则，下一轮任务更少、更准。

## 旧平台能力在这里怎么落地

| 旧平台能力 | zw-brain 表达 | 用户感知 |
| --- | --- | --- |
| 申请和审批边界 | `application_record` / `approval_case` | 知道汇总服务哪个需求 |
| 目录模板字段 | `catalog_item` / `catalog_model_field` | 用统一口径审核基层差异 |
| 资源字段绑定 | `resource_schema_mapping` | 异常能定位到资源字段 |
| 质量检测 | quality projection | 只处理真正异常 |
| 汇总撤回 / active 版本切换 | summary snapshot + audit receipt | 发现口径错配时可回放影响范围 |
| 供需 / 用数 / 异议 | supply-demand / usage / objection projection | 从治理大盘定位问题，不线下重算 |
| 数据直达 | 已审批数据直达交付回执 | 只允许已审批、可追踪交付 |
| 交付与回流 | `delivery_task` / 回流资源池 | 汇总结果进入可复用链路 |
| 异议处理 `dsp_handling / data_objection / data_objection_evaluate / data_objection_process / data_objection_authz / data_objection_use` | 评估 / 处置 / 授权 / 用数 四段 projection | 异议不再口头解决，每段都留痕 |
| 需求任务派发 `dsp_require / data_require_task_link` | demand task link + 基层任务卡 | 业务需求不可复用时按差异切卡派发 |
| 自动检测任务失败 `catalog_quality_task_log` | 受影响汇总范围标注 | 不替 R6 改规则，不替 R8 查执行器 |
