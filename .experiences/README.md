# zw-brain 角色体验手册：M0 一次性迁移验收 + R1-R8 稳态治理旅程

这套文档不是旧后台操作手册，也不是把旧平台迁移工作分摊给 8 个角色。旧 catalog/metadata 后台的完整能力都要承接住，但旧平台退场只由 M0 一次性完成；R1-R8 不再承担导入、核验、补迁、重跑或回滚，而是在验收后的目录、资源、证据和投影上完成稳态工作。

M0 结束后，旧对象来源可以回指 `legacy_object_mapping`，但这个回指只是来源证据，不是每个角色的日常动作；R1-R8 只处理用户可感知的发现、申请、审批、补差、汇总、资产治理、目录运营和合规督查。每一次目录、资源、申请、授权、发布动作都进入 Capability、策略和审计链；统计、质量、血缘、采集状态只作为可重算 `projection`，不反向改业务事实。

## 先做一次 M0，再进入 8 个常驻角色

M0 是旧平台退场、zw-brain 开箱的迁移与验收旅程；它只发生在客户现场交付阶段，不是第 9 个长期角色。M0 通过后，R1-R8 才开始接手日常工作：R6/R7/R8 负责稳态治理，R1-R5 负责业务使用。

| 类型 | 旅程 | 这一棒交付什么 |
| --- | --- | --- |
| 一次性 | M0 客户现场迁移与验收 | 从旧平台一键导出、批量导入、映射核验、迁移审核、缺口补批到验收移交 |
| 常驻 | R1 上级业务需求发起人 | 先发现可复用目录和资源，再提交最小必要申请；只看来源证据，不碰迁移动作 |
| 常驻 | R2 区县/部门审批承接人员 | 判断复用、补录、驳回或授权边界，防止重复要数；证据缺口退回 M0/R7，不在审批页补造来源 |
| 常驻 | R3 镇街填报人员 | 接收预填后的补差任务，只补现场变化，不为迁移补表 |
| 常驻 | R4 村社区填报人员 | 用轻量任务卡完成末端核实，不接触复杂治理后台和旧表 |
| 常驻 | R5 镇街/区县审核汇总人员 | 盯异常、口径、完成率，确认自动汇总和回流；不线下重算旧数据 |
| 常驻 | R6 数据提供方/台账管理员 | 把验收后的资源、字段、schema 和安全证据整理成可复用资产 |
| 常驻 | R7 数据共享/目录管理员 | 让验收后的目录发布后可发现、可申请、可授权、可解释 |
| 常驻 | R8 合规运营/督查人员 | 用日常链路证据证明是否减负、是否绕行、哪里断链；只督查 M0 证据，不执行迁移 |

## 旧页面如何压缩成新旅程

旧系统的几十个页面不再被复刻为几十个入口，也不把迁移责任塞进每个角色，而是压缩成一条一次性迁移主线 + 八条稳态主线。

| 旧页面群 | zw-brain 旅程主线 | 主要承接 |
| --- | --- | --- |
| 目录查询、已发布目录、共享专区、目录分组 | 发现申请 | R1、R7 |
| 目录审核、牵头部门审核、关联审核、分级授权、续期 | 审批授权 | R2、R7、R8 |
| 基层任务、质量提示、退回修改、汇总确认 | 补差汇总 | R3、R4、R5 |
| 数据源、前置库、文件服务器、元数据采集、资源注册、资源维护 | 提供方治理 | R6 |
| 目录维护、分类关联、资源挂接、国家目录资源挂接、反向编目 | 目录运营 | R7、R6 |
| 审计日志、质量报告、关系图谱、血缘断链、绕行导出 | 合规督查 | R8 |
| 客户现场导出、批量导入、目录迁移审核、映射核验、回滚重跑 | 迁移实施 | M0 |

## 敏感信息纪律

体验文档可以写目录名、组织名、区域名、状态名、字段口径名；不得写个人明细、联系方式、证件号、数据库连接信息、内部地址、附件路径、原始错误堆栈、原始工单沟通文本。需要表达这些内容时，只写“已脱敏证据引用”“密钥引用”“外部执行器上下文”或“错误摘要”。

## 验收这套体验文档

- M0 能说清旧平台如何一次性导出、迁移、核验、重跑、回滚和移交。
- R1-R8 都能说清自己在同一条资源治理链里的位置。
- 每个角色至少有真实目录、组织、区域、状态或字段口径示例。
- 旧 catalog/metadata 后台的完整能力在矩阵中有承接位置。
- 用户看到的是“M0 迁得清；R1-R8 找得到、要得清、交付稳、证据可追”，不是两个旧后台换皮。
- 任何结论都能回到目录、资源、字段绑定、schema 快照、申请审批、交付回执、projection；需要追溯旧对象时，再引用 M0 生成的 `legacy_object_mapping`。
