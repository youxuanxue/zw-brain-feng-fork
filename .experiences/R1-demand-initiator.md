# R1 上级业务需求发起人：先找得到，再要得清

## 这一页解决什么事

你要在专题、督查或统计时限内拿到可靠数据。zw-brain 不鼓励你一上来新建采集表，而是先从已验收、已发布、可申请的目录与资源证据里找可复用资产，只把真实缺口交给后续补录。

## 你手上拿到的真实输入

- 业务目标：例如民生保障专题、医保协同、异地就医统计。
- 候选目录：民生类 `医疗救助信息`、`医保码信息`、`异地就医统筹区开通信息`、`参保信息`、`城乡居民养老保险参保登记`；监管类 `产品质量监督抽查信息`、`必需经水路运输医疗废物审批信息`、`案件信息`。这些都是旧 `dump-dsp_catalog` 中真实存在的 sd-default 目录。
- 字段口径：`字段名称`、`字段备注`、`字段格式`、`安全级别`、`是否需要加密`、`授权类型`。
- 资源状态：目录是否 `发布`，资源是否可申请，schema 快照是否仍有效。
- 来源证据：M0 验收后的对象来源引用，目录项是否能解释到资源字段。
- 门户入口：旧 `portal-vue` 的首页、政务数据目录、政务数据资源、搜索结果、知识中心、资源申购车和反馈。
- 应用入口：旧 `app-center-web` 的我的应用、我的资源、应用查询、应用注册和资源申购车。
- 反馈四类：`portal-vue /feedback/*` 在旧 `FeedbackView.vue` 真实分为数据异议、网站反馈、资源申请异议、数据使用异议。
- 申购车两端：旧 `portal-vue /res-purchase-car` 与 `app-center-web /res-purchase-car` 在新平台合并为同一份"申请草稿"，不分裂成两套系统。
- 需求登记前置（旧 `dsp_require`）：在你确认"现有目录满足不了"前，先以"原始需求"形式登记（用途、字段口径、时间窗、责任部门）；R7 判断能否用现有目录复用；不可复用才升级为"业务需求"并派发 R5 任务。需求登记不等于申请，是申请的上游证据。
- API 凭据与调用回执（旧 `dsp_service`）：交付通道是 API 时，授权生效后会发放 API 凭据（密钥引用、IP 白名单范围、限流额度），调用统计与错误样本回流到"我的应用"。
- 旧状态映射：旧 `审核中(2)/发布(3)/撤销` ↔ 新 `pending_review/active/revoked`；申请生命周期以 catalog3-metadata3 重构方案 §八 为准。

## 一条主旅程

1. 从首页、政务数据目录、政务数据资源或搜索结果进入发现页，输入“医保”“救助”“异地就医”等业务词，系统优先返回已发布 `catalog_entry`，并把共享专题、推荐目录和订阅更新放在同一屏。
2. 如不清楚口径，先看知识中心里的政策、培训和典型应用案例；这些只帮助理解，不替代正式申请。
3. 打开 `医疗救助信息`，先看目录说明、提供方、区域范围、共享条件、更新周期、开放条件和字段清单，而不是直接发新采集。
4. 对比 `医保码信息` 的字段口径，确认哪些字段可直接复用，哪些字段因 `安全级别` 或 `是否需要加密` 只能申请脱敏、汇总或授权后的结果。
5. 查看资源可交付性预览：`resource_asset` 是否 active，通道是库表、文件、文件夹、链接还是 API/接口，`resource_schema_snapshot` 是否有中文注释、字段格式、采集时间和交付频次。
6. 看清目录项到资源字段的 `resource_schema_mapping`；目录已发布但资源不可交付时，不把它当作可用能力。
7. 把候选目录、资源或接口加入资源申购车；门户和应用中心两个入口共享同一份申请草稿，用来组织最小必要范围，不是让用户批量囤数。
8. 如果数据用于某个应用，在应用查询或应用注册里说明应用名称、用途、代理调用边界和责任人；应用只是用途证据，不成为第二套平台中心。
9. 对无法满足的部分形成缺口字段，例如时间窗、地区范围或口径差异，而不是把整张表重报。
10. 提交 `application_record`，写清用途、时间窗、申请范围、目录项、缺口字段、期望交付方式、应用/代理使用边界和是否需要订阅后续更新。
11. 在我的资源、我的应用和状态时间线里跟踪 `待受理`、`审核中`、审批结论、授权生效、续期提醒和后续 `delivery_task`，让需求进入 R2 审批与后续补录链。
12. 如果一开始还不能确定要哪些目录，先用"需求登记"前置：写明用途、字段口径、时间窗、责任部门，提交给 R7 做"可否用现有目录复用"判断；R7 反馈"可复用"则回到第 3 步直接申请，"不可复用"则进入业务需求与后续基层补差任务。
13. 如果交付通道是 API/接口，授权生效后到我的应用领取 API 凭据（密钥引用、IP 白名单范围、限流额度），按返回的端点和入参调用；订阅页能看到调用计数与错误样本，发现异常时看授权与凭据是否仍有效，不在线下截图问人。

## 关键判断点

| 你看到什么 | 该怎么判断 | 系统证据 |
| --- | --- | --- |
| `医疗救助信息` 已发布 | 优先复用，不新增采集 | `catalog_entry.status=active`，发布审计回执 |
| 字段口径和业务目标基本一致 | 只申请必要字段 | `catalog_item`、`catalog_model_field` |
| 字段敏感级别较高 | 申请脱敏、汇总或授权后的结果 | 字段策略快照、`delivery_task.access_grant_snapshot` |
| 资源字段能解释目录项 | 可进入复用申请 | `resource_schema_mapping`、`resource_schema_snapshot` |
| 目录存在但资源不可交付 | 不直接催基层，先发起资源治理问题 | `resource_asset.status`、quality projection |
| 同主题目录很多 | 优先看推荐、订阅量和共享专题解释 | topic projection、搜索排序证据 |
| 交付通道是 API/接口 | 先看调用边界、频次和授权条件 | `resource_channel_binding`、授权策略快照 |
| 申购车里候选很多 | 合并同主题诉求，只保留最小必要申请 | 申请草稿、目录/资源证据 |
| 我的资源已有授权 | 直接复用或续期，不重新申请 | `delivery_subscription`、授权快照 |
| 我的应用需要代理调用 | 明确应用用途、责任人和调用边界 | 应用用途快照、代理授权边界 |
| 不确定用哪份目录 | 先做"需求登记"，让 R7 反查复用 | demand-resource link、原始需求草稿 |
| 业务需求与现有目录差距很大 | 转 R5 基层补差任务，不直接发新采集 | demand task link、基层任务派发 |
| 交付通道是 API 但 IP 不在白名单 | 不在调用端绕过；回审批补 IP 范围 | `api_access_ip`、授权策略快照 |
| API 调用被限流或熔断 | 看是否在配额内、是否需调档；不偷换密钥 | `api_service_counter`、`api_service_fuse` |
| API 凭据过期或被吊销 | 走续期或重新申请，不复用历史密钥 | 授权快照、密钥引用 |

## 异常分支

- **没有命中目录**：扩大关键词并看专题分组；仍找不到时，提交目录草稿建议，不直接发基层采集。
- **字段口径冲突**：把冲突写到申请备注，触发 R6/R7 确认目录项和资源字段绑定。
- **申请范围过大**：R2 可要求缩小到具体区域、时间窗或脱敏粒度。
- **审批退回**：按退回意见减少字段、改成阶段性交付或补充最小必要说明。
- **资源 schema 过期**：先进入提供方治理，不把过期资源当作已交付能力。
- **知识中心内容和目录证据冲突**：以目录、资源、授权和审计事实为准，知识内容只作为解释材料。
- **申购车范围膨胀**：拆成更小的申请或删除非必要资源，避免“一车全要”。
- **反馈授权异常**：反馈按四类分别提交——数据异议（口径/质量/血缘）、资源申请异议（审批/范围）、数据使用异议（交付/直达结果）、网站反馈（页面问题）。所有类型都进入证据链，由 R2/R5/R7/R8 定位审批、授权或投影问题，不回到线下沟通。
- **需求登记被当成"占坑"**：不可用需求登记圈占资源；只能写明用途与时间窗，R7 复用判断后再升级或关闭。
- **API 调用错误反复出现**：先看 `api_service_errors` projection，再决定是回审 IP 白名单、限流档位、字段脱敏还是订阅终止；不在调用端绕过。

## 成功判据

- 你提交的是复用申请，而不是裸新增采集。
- 每个申请字段都能说明来自哪个目录项、哪个资源证据或哪个缺口。
- 审批、授权、交付状态可以在同一条时间线上回放。
- 基层只收到真实缺口任务，不再为已存在数据整表重填。

## 旧平台能力在这里怎么落地

| 旧平台能力 | zw-brain 表达 | 用户感知 |
| --- | --- | --- |
| 目录查询 `data_catalog` | `catalog_entry.query` | 先找目录和可申请边界 |
| 目录信息项 `data_catalog_column` | `catalog_item` / `catalog_model_field` | 看字段口径、敏感级别、共享条件 |
| 资源挂接 | `resource_schema_mapping` | 知道目录项对应哪类资源字段 |
| 资源申请 `data_apply*` | `application_record` | 提交最小必要申请 |
| 授权与交付 | `delivery_task` | 跟踪授权是否生效、交付是否完成 |
| 已发布目录 / 共享专区 / 目录分组 | topic projection / search projection | 按业务任务找到推荐目录和订阅更新 |
| API/接口资源查询 | `resource_channel_binding(kind=api)` | 提前知道调用频次、授权边界和交付方式 |
| `portal-vue` 首页 / 知识中心 / 反馈 | discovery help / ops issue | 先理解口径，异常进入证据链 |
| 资源申购车 | 申请草稿快照 | 收集候选后提交最小必要申请，门户与应用中心共用同一份草稿 |
| 反馈 `portal-vue /feedback/*` | 四类反馈进入证据链 | 数据异议 / 资源申请异议 / 数据使用异议 / 网站反馈 |
| 我的资源 / 我的应用 | `delivery_subscription` / 应用用途快照 | 查看已授权资源、交付状态和应用用途 |
| 应用查询 / 应用注册 | 应用用途快照 | 用途和责任边界进入审批证据 |
| 需求登记（旧 `dsp_require / data_original_require / data_business`） | 原始需求 / 业务需求 草稿 + R7 复用判断 | 不确定时先登记，由 R7 判定能否复用 |
| API 凭据领取与调用（旧 `dsp_service / api_service_*`） | 我的应用 + API 凭据 + 调用计数 projection | API 是一种正式交付通道，不是"自由调用" |
