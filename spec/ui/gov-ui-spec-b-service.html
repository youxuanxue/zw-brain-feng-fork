UI Spec B · 一网通办服务（细化稿）

版本：2026-04-29 · 适用范围：一体化政务办事大厅、事项检索、服务聚合首页（H5 / Web 同源收敛）

1. 设计原则

  • 检索优先：首屏核心动线是「搜事项 / 搜指南」，次要入口通过频道与服务图标承接。
  • 三色系收敛：主色服务蓝、辅色青绿（用于次级强调或分类区分）、中性灰阶；避免引入第四种色相。
  • 扁平服务图标：入口图标统一为圆形底 + 面性图形隐喻；逻辑尺寸 96×96（CSS 可按密度缩放，保持比例）。
  • 低干扰：禁用自动轮播首屏 banner；悬浮推广须可一键关闭；动效遵循用户系统「减少动态效果」偏好。
  • 与门户区分：本 Spec 侧重「办事」，长文政策阅读页可复用组件但倾向更宽正文栏与更强目录导航（不在本页展开）。

3. 语义字体与字号契约

实现层必须使用下列语义类表达字号；业务页面不得直接散落 text-sm、text-xs 或任意裸字号。

语义类 / 组件槽位 尺寸 / 字重 / 行高 用途
text-display 30px / 700 / 1.2 关键数字、强展示值；必须启用 tabular-nums。
page-hero-title 24px / 700 / 1.3 页面主标题；每页首屏只出现一次。
panel-title 18px / 700 / 1.4 卡片、模块、侧栏标题。
row-title 16px / 600 / 1.55 列表行主标题、表单字段值。
text-body 15px / 400 / 1.65 业务正文、说明文案、列表内容。
text-body-sm 14px / 400 / 1.65 面包屑、次级正文、卡片补充说明、meta 信息。
text-caption 13px / 400 / 1.5 短状态、时间、角标；不得用于面包屑主路径。

字体栈固定为 Microsoft YaHei, PingFang SC, Noto Sans SC, system-ui, sans-serif。英文与代码混排时保持同一行高层级。

4. 语义间距、圆角与层级契约

语义对象 标准值 约束
页面容器 桌面左右 24px，内容最大宽 1500px 主 WebUI 与 dashboard 必须同宽对齐。
面包屑到首卡 mb-2 = 8px 不得使用 mb-4 造成首屏空洞。
page-hero 内边距 8px 11px 服务型首卡保持紧凑，不做展示型大横幅。
panel-body 20px 22px 承载业务内容的普通卡片保持舒展。
模块间距 16px / 20px / 24px 优先使用现有 gap-4、gap-5、space-y-5，避免临时裸值。
圆角 6px / 10px / 16px / pill 控件、卡片、大卡、胶囊四级；同组件不得混用。
阴影 0 2px 8px rgba(0,80,180,.08) 禁止强投影和 dark cockpit 氛围。

5. 语义组件契约

实现层优先复用下列组件语义；新增组件必须先登记到本表，再进入 CSS 与页面模板。

组件 / 类名 用途 硬约束
crumbs 页面路径提示 使用 text-body-sm + mb-2；不得使用 caption 级字号。
page-hero 页面首卡，承载标题、说明、状态 白底浅蓝边框，紧凑内边距，禁止外层大框和深色背景。
panel 普通业务卡片 统一白底、浅蓝边、低阴影；标题使用 panel-title。
gov-stat-card 指标卡片 标题、数值、注释、动作分别使用 gov-stat-label/value/note/action。
gov-btn 按钮 主按钮每个局部任务区只保留最强动作；颜色必须来自 token。
status-pill / chip 状态与短标签 只表达状态，不承担正文说明；使用 success/warn/danger/neutral 语义色。

6. 禁止项与扩展流程

  • shipped WebUI 禁止出现 Spec B、一网通办、Command View 等规范或 cockpit 文案。
  • 禁止 Tailwind CDN、inline theme、legacy navy（#12386f / #1d5a9f）与 dark cockpit palette。
  • 页面模板禁止使用裸 text-sm / text-xs 表达业务字号。
  • 新增颜色、字号、间距、组件前，必须先登记到本规范，再同步 CSS 与 preflight 门禁。

7. 参考组件细则

7.1 全局检索条

  • 高度：触控友好 ≥44px（padding 计入）；桌面可适当收紧。
  • 结构：左侧输入（占位提示「搜索办事指南 / 事项名称」），右侧主按钮「搜索」。
  • 焦点：键盘聚焦时整条描边 + box-shadow 形成 3px 聚焦环（见按钮演示）。
  • 清空：有输入时右侧显示文字按钮「清空」，不占用主色按钮位。

7.2 服务图标（入口矩阵）

  • 形状：正圆外框 + 内嵌面性图标（线性点缀不超过图标面积 20%）。
  • 尺寸：设计稿 96×96；栅格 4 列（桌面）→ 2 列（窄屏）。
  • 配色：沿用主色 / 辅色 / 两组中性点缀色（如紫、橙）仅限图标底，不在页面大块背景使用。
  • 文案：图标下 12–13px 单行标题；复杂入口加一行 11px 灰色说明（可选）。

7.3 分区 Tab（事项列表上方）

  • 数量：同一层级 3～5 个；更多收纳进「更多」下拉或二级页。
  • 状态：选中 = 主色填充白字；未选中 = 白底主色字 + 浅描边。
  • 可访问性：使用 role="tablist" / role="tab" 或与路由同步的按钮组，保证箭头键与屏幕阅读器语义。

7.4 事项列表行

  • 每行：左主标题（14px）+ 右办事类型标签（全程网办 / 预约制 / 指尖办等）。
  • 交互：整行可点（<a> 或 button）；hover 背景 rgba(0,107,230,0.06)。
  • 分隔：虚线 1px dashed #d4e2f4；最后一行无分割线。

7.5 按钮层级

主按钮仅每屏 1 个「最强动作」（通常为检索或「在线办理」）；并列表格场景允许双主按钮需设计评审。

9. 无障碍与适老化衔接

  • 对比度：主正文与背景对比建议 ≥ 4.5:1；主按钮蓝底白字需实测（不满足则加深 --b-primary）。
  • 焦点可见：所有可交互元素保留浏览器默认或自定义 3px 聚焦环。
  • 长者版：Spec B 可作为标准版；切换到长者版时采用更大字号与更低信息密度（可参考 Spec C 规则单独覆盖 Token）。

10. 与公开指引条款的对照（摘要）

指引要点（摘要） Spec B 落地
整体简洁、风格统一、符合 Web 标准取向 单一路径办事首页；组件 Token 化；避免多风格混拼
主色一种 + 辅色，全站色相不宜超过三种 蓝主 + 青绿辅 + 中性灰；图标点缀色限用于小面积图标底
头部标识区 / 中部内容区 / 底部功能区 顶栏品牌与辅助入口；中部检索 + 服务 + 列表；底栏法定要素
