这不是一组说明页，而是一套可直接验收的政务协同主链路原型。

从“先复用模板”开始，经过受控准入、差异补录、审核汇总、回流共享，到减负治理与只读指挥投影，所有关键动作都应在跨页状态、证据链和治理投影上保持连续一致。

本轮验收口径
1. 看链路是否真实
同一事项要跨 R1–R8 连续流转，而不是每页各说各话。
2. 看状态是否同步
列表、详情、时间线、治理页、大屏投影要一起变化，不靠 toast 假装完成。
3. 看失败是否诚实
退回补正、驳回、熔断和快照模式必须被明确表达，不能伪装成成功。
4. 看 AI 是否守边界
AI 可以减摩，但不能替代责任主体做主状态写动作。
主内容区会根据当前路由切换到 P1–P8 / K12，对应状态机、时间线与审计证据同步刷新。 不靠静态说明页
评审时优先盯住这四件事
  • 模板复用：先找“法人单位基础信息台账模板”，不要让基层从零填表。
  • 差异补录：基层只补共享池缺的现场差异字段，而不是重填整张表。
  • 回流沉淀：本次补录结果应变成下次默认模板能力，而不是一次性人工劳动。
  • 治理投影：P6 与 K12 看到的是减负结果、异常责任链和证据，不是后台日志。
关键守卫
任何“批准 / 汇总确认 / 回流共享 / 能力上线”都必须保留人工确认动作。
指挥大屏是独立只读投影；主大脑异常时进入快照模式，而不是接管办理态。
被退回、驳回或熔断时，要在链路上留下清晰阻断语义与审计证据。
