# 场景 3：R3 / R4 预填补录 → R6 / R7 回流共享

**适用角色**：R3 镇街填报人员、R4 村社区填报人员、R6 台账管理员、R7 目录管理员。

**目标**：验证基层只补差异字段、审核后形成回流候选、供给侧再把结果沉淀成下次可复用模板能力。

## 进入路由

1. `#/p3-request-flow/request/REQ-2026-04-25-0011`
2. `#/p4-delivery-exchange`
3. `#/p4-delivery-exchange/task/DLV-2026-04-25-0011`
4. `#/p5-provider`
5. `#/p7-zones-pack/zone/business`

## 关键动作

### A1｜R3 / R4 差异补录
- 角色切到 **R3** 或 **R4**。
- 在请求详情页确认“已预填字段”和“待补录 / 差异字段”已被分离。
- 点击 **提交差异补录**。

### A2｜查看交付与自动汇总衔接
- 打开 `#/p4-delivery-exchange`。
- 确认任务状态、回流状态和动作提示已联动更新。
- 进入 `#/p4-delivery-exchange/task/DLV-2026-04-25-0011` 查看回流候选对象与下一动作门槛。

### A3｜R6 / R7 确认回流共享
- 在完成汇总确认后，点击 **确认回流共享**。
- 再查看 `#/p5-provider` 和 `#/p7-zones-pack/zone/business`。

## 预期状态变化

- A1 之后：
  - 请求进入“待汇总确认”。
  - 差异字段显示为已补录。
  - 交付任务从补录阶段进入待汇总语义。
- A2 之后：
  - 任务详情展示“当前还未满足回流确认条件”或“当前可确认回流”，与请求状态一致。
- A3 之后：
  - 回流状态变为“已确认”。
  - 模板版本、回流说明、专题入口信任信息同步变化。
  - 页面能表达“这次补录沉淀成了下次直接复用的资产能力”。

## 审计 / 证据点

- 预填来源、差异字段责任人、补录时间可回溯。
- 自动汇总结果与回流候选说明可回溯。
- 回流确认记录、模板升级说明和专题入口同步痕迹可回溯。

## 本场景验证哪条 v4 主张

- R3 / R4 是否真正从整表填报转成差异补录。
- P4 是否把交付、自动汇总、回流做成单一闭环。
- R6 / R7 是否能把一次补录沉淀成下一次默认复用能力。
