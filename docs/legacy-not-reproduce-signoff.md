> **本文用途**：旧平台 V5.0.2 冒烟用例 128 条中，**50 条 ❌ 不复刻**需要业务方亲笔签字接受。不签字 = 客户上线后发现"旧的能新的不能"的风险责任不明。

签字判定语义：

- **接受**：业务方确认本类别 zw-brain 不重做；客户上线时由外部能力包 / 业务流程绕路承接 / 业务方主动放弃
- **复活**：业务方坚持本类别 zw-brain 必须重做；需进入 GATE 流程重新立项
- **部分复活**：业务方接受大部分不重做，但有特定子项必须保留；需在判定栏右侧列具体子项

## 三、复活的代价（业务方决策辅助）

若业务方判定某类别为"复活"或"部分复活"，需评估：

| 复活类别 | 工程成本 | 飞轮影响 |
|---|---|---|
| A 融合 / 通用 / 代理服务 | 高（4-6 worker·month）| 减速 — 长尾耦合 |
| B 大屏 / 数字化运营 | 中（2 worker·month）| 中等减速 — 独立部署单元 |
| C 数据治理（内造）| 极高（>6 worker·month）| 严重减速 — §3.4 反 |
| D 主题库 | 中（2 worker·month）| 中等减速 — D30 forbidden-zone |
| E 栏目管理 | 低（0.5 worker·month）| 微减速 |
| F 知识中心独立 | 低（0.5 worker·month）| 微减速 |
| G 多 SPA | 极高 | 极严重减速 — 反 R1 |
| H 应用中心 | 中（2 worker·month）| 中等减速 |

**Jobs 视角**：每复活一类 = 飞轮加速器 #2（R14 三引擎）失效一份。复活越多飞轮越慢。

## 四、客户上线后的反查（飞轮 ritual）

每个客户上线 30 天内，回访客户对本清单 8 个类别的实际诉求：

- 客户未提任何类别需求 → 本清单维持
- 客户提出某类别需求 → 走 GATE 流程评估复活 OR 外部能力包承接 OR 业务流程绕路

回访结果回灌到 `docs/customer-readiness/wave4-cutoff-criteria.md` §一.D 长尾发现清单。
