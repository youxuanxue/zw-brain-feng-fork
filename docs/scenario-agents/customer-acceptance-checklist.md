## 二、用数方（找数）· A① 数据发现副驾

| # | 验收点 | 怎么验 | 通过判据 | 状态 |
|---|---|---|---|---|
| U1 | **一句话→资源推荐**：用大白话说需求，副驾给出可申请资源的 TOP-N | 输入"我想找企业纳税和停车场相关的政务数据" | 返回排序后的候选资源清单（带目录名/编码），而非让我自己翻菜单 | ✅ live 实测：GLM-4 自主检索后给出"企业年报信息""山东省企业登记基本信息"等推荐 |
| U2 | **术语对齐**：我说的口头词≠平台目录词时，副驾帮我对上 | 输入含平台没有的说法（如"企业纳税"） | 明确提示"该说法暂无对应条目"并给出平台规范替代名词 | ✅ live 实测：返回"企业纳税暂无对应条目，建议用企业年报/登记信息" |
| U3 | **只推可申请的**：不要把下不了的、未发布的资源推给我 | 检索词命中草稿/未发布资源 | 结果只含已发布（active）资源，不出现断头路 | ✅ 证据：J1 找数回归 + 数据应用真实 UI e2e |
| U4 | **不编造**：检索不到就说没有，不要瞎编资源 | 输入平台确实没有的冷门需求 | 明确回答"未找到相关资源"并给追问建议，不虚构目录编号 | ✅ live 实测：A① 给追问建议、不杜撰 |
| U5 | 副驾以**页内嵌**形态服务，不污染顶级问答入口 | 查看顶级智能体问答列表 | 该副驾不出现在顶级列表（`exposes_chat=false`） | ✅ 证据：tier-1 |
| U6 | 把"推荐+术语对齐"**直接嵌进 P2 找数页 UI** | 在 P2 页内点用副驾 | 页面内出现副驾交互、给出推荐 | ⏭️ 后续交付：当前 P2 页直连搜索能力、未接该智能体 UI（需 web→`/api/agent-runtime` 接线，另立一条交付） |

## 四、数据治理 / 安全（最小权限 · 合规）

| # | 验收点 | 怎么验 | 通过判据 | 状态 |
|---|---|---|---|---|
| G1 | **敏感字段映射最小权限**：基础操作员看不到失信/纳税信用等敏感字段映射 | 以基础操作员（ROLE_ORGAN_OPERATER）触发字段映射查询 | 被拒绝（仅 manager/运营/审计可读） | ✅ 证据：policy 角色矩阵 + B1/J1 回归测试 |
| G2 | **运行时角色生效**：副驾按调用者真实角色裁剪可用能力 | 同一副驾分别以不同角色调用 | 角色不足时相应能力被拒、不越权 | ✅ 经平台 policy 角色矩阵；G1 即一例 |
| G3 | **全程可审计** | 查询审计事件 | 副驾每次工具调用进审计总线、可追溯 | 🟡 平台审计总线既有能力承载，待你在审计面复看本副驾调用记录 |
| G4 | **不触发外部 Agent 接入风险（T1）** | 审查 B 试点形态 | 为平台内置 Agent，由独立 AgentRuntime 服务运行但随 zw-brain 仓库发布，不走外部第三方注册流水线、不触发 T1 | ✅ 证据：内置 Agent manifest + D68 单一模型守卫 |
